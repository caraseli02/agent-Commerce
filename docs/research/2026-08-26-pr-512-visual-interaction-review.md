## Findings by priority

### Confirmed PR regressions

None established. Controlled comparison of fresh PR and `origin/main` found the dashboard order route, virtualized page-size behavior, mobile Enter handler, dual product lookup routes, and `ord-2` confirmation path unchanged or equivalently functional.

### P3 — baseline observations and coverage limits

1. **[P3, baseline] Quick Buy row-removal buttons are unnamed.** The desktop Quick Buy DOM exposed unnamed removal buttons. This is an accessibility follow-up, but the touched `QuickBuy.vue` change is a guard-only edit and no baseline regression was demonstrated. Evidence: [Quick Buy dialog](pr-512-screenshots/checkout-order/02-quick-buy-dialog-desktop.png).

2. **[P3, baseline] The empty-cart sheet has no meaningful empty state.** Removing the final item left only the “Shopping Cart” header and the console reported an unresolved `GlobalEmptyState`. The cart empty-state component is outside this PR’s changed files, so this is not attributed to #512. Evidence: [empty cart](pr-512-screenshots/checkout-order/04-cart-empty-after-removal.png).

3. **[Coverage limitation] Search filters could not be exercised.** The mock search response returned `filters: {}`, so the filter UI had no facet metadata. This prevents coverage of the changed filter parsing/guard code; it is not a product regression finding.

4. **[Coverage limitation] Notification mark-read/delete could not be exercised.** The authenticated mock admin returned zero notifications. Open, Orders-tab, and close behavior were verified; item actions remain unverified.

5. **[Coverage limitation] `ProgressBar` was not reachable.** Both desktop and mobile `/control-panel/settings` routes redirected to `/control-panel/account`, so the touched ProgressBar/chart code and widget-card path remain unverified. No regression claim is made.

6. **[P3, transient] Similar-product CTA once missed while async state settled.** Clean retries succeeded on desktop and mobile; retain only as a race-risk note, not a confirmed defect.

7. **[P3, baseline-looking console noise]** Hydration mismatch, missing dialog description, reactive-component, extraneous-attribute, non-element transition, and `NUXT_E1003` warnings appeared in broader shell/auth flows. They were not reproduced as branch-specific regressions and remain separately classified below.

## Runtime/console classification

### Observed on current flows, but not established as PR regressions

- Unnamed Quick Buy removal buttons and blank empty-cart state are baseline-looking UI/accessibility issues outside the changed behavior.
- Fresh current and `origin/main` direct dashboard order loads were clean; no active-Pinia error was reproduced in the controlled comparison.
- Fresh current `/dashboard/orders/ord-2` rendered without a `TypeError` or `adminSettings` error; the earlier claim is withdrawn.
- The one earlier Secure Checkout HTTP 500 was not reproduced after restart and was not baseline-compared; it is not treated as a PR finding.

### Repeated but treated as unrelated/pre-existing for this PR

Hydration mismatch warnings appeared repeatedly across home, search, cart, checkout, product detail, and dashboard flows: cart count/total, client-priced product values, footer links, and auth-dependent labels differed between SSR and client, followed by `Hydration completed but contains mismatches.` The PR changes strictness guards and several touched components, but does not change the cart hydration source, footer link data, or the auth/cart bootstrap contract. These are recorded for follow-up, not attributed to the PR without a baseline comparison.

The unresolved `GlobalEmptyState` warning in the cart sheet, missing dialog descriptions, reactive-component warnings, and `NUXT_E1003` warning likewise appeared in broader existing shell code outside the PR’s changed lines. They remain visible defects in the review environment, but are classified separately from confirmed PR-surface regressions.
